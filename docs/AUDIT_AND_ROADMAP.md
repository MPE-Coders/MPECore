# MPECore: порядок реализации

Это план, не перечень уже работающих возможностей. Проект остаётся экспериментальным; текущий патч не объявляет выпуск 1.0.0-alpha.

## Текущий проверяемый блокер

Пользователь подтвердил успешную Rust release-сборку и standalone-тесты. Запуск 1.26.20/975 останавливается в проверке обратного декодирования StartGame до открытия UDP: не инициализировано поле `serverTelemetryData` перед передачей по ссылке в NetherGames LevelSettings::read.

Патч вводит свежую нейтральную инициализацию объекта для decode, а не отключает проверку. Реальный вход официальным клиентом пока не подтверждён. См. `TEST_REPORT.md` и `docs/TESTING.md`.

## Ближайшие рубежи

### A. Один проверенный игровой цикл

Чистая сборка, настоящий IPC и сохранение, installed-codec проверки, вход официального клиента одной точной версии, движение, чат, хотбар, установка/разрушение, повторный вход. Отдельно фиксировать результат headless-клиента и официальной игры. Не расширять число рекламируемых протоколов вместо этой проверки.

### B. Единая модель мира

Заменить `BlockStateId=u8` и 12 состояний расширяемым `StateId(u32)` с типизированным реестром и компактной палитрой секций. Перевести IPC и storage вместе с явной миграцией старого WAL и backup. Убрать независимо зашитое чтение плоской травы: генерация, collision и отправка чанка используют одного владельца состояния. Реализовать формы неполных блоков, block entities, биомы, snapshots и compaction.

### C. Creative-мультиплеер

Взаимная видимость игроков, skins, tracking, equipment, одинаковое состояние мира у двух официальных клиентов, permissions/whitelist, time/weather, сохранение игроков. Полный каталог выбранной версии не равен полной реализации поведения.

### D. Обычный мир и базовый Survival

Крафт 2x2/верстак, shaped/shapeless recipes, печь/топливо, сундуки, инструменты/прочность, дропы/подбор, здоровье/голод/урон, смерть/respawn, свет и базовая физика. Приёмка: дерево -> инструмент -> руда -> переплавка -> сундук -> перезапуск без потери или дублирования.

Генератор Pumpkin — кандидат для адаптации, не уже встроенный компонент. Нужны компилируемый адаптер, сопоставление состояний, стадии соседних чанков и сравнение с официальной редакцией/версией/seed/settings. Версию генератора хранить в карте; exact Bedrock parity не заявлена.

### E. Расширение и независимость

Мобы/AI/navigation/spawn, животные/размножение, жители/торговля/POI, редстоун/поршни/порядок обновлений, Nether/End/порталы/дракон, структуры/loot, enchant/brew/fishing/vehicles. Отменяемые plugin-события требуют pre-commit контракта с deadline; существующий BlockChangeEvent — уведомление после изменения. Ресурс-паки старых клиентов не добавляют отсутствующие функции их движка.

Нативный Rust gateway внедряется по этапам из `RUST_MIGRATION.md`; PHP API сохраняется как необязательный plugin-host.

## Обязательная матрица состояния контента

Для каждого блока/предмета вести отдельные признаки: registry -> wire encoding -> rendering -> interaction -> persistence -> official-client test. Печь в NBT-палитре не означает рабочую плавку; нельзя считать каждый non-air блок полным твёрдым кубом.

## Организация исходников

Всё находится в `MPE-Coders/MPECore`. Не нужны отдельные репозитории для текущего исправления. Версии будущих модулей, IPC, plugin API и формата мира независимы. Зависимости собираются из lock-файлов; vendor, runtime, миры, токены и кэши не публикуются в исходниках.
