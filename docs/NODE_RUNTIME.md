# Node 22 на системе, Node 24 внутри MPECore

Сообщение `2193 requires Node >=24` при Node.js v22.22.1 — несовместимость
версии runtime, не сбой аккаунта, Rust, NBT или номера Bedrock-протокола.
Для временного 2193 codec bridge и тестового клиента требуется Node >=24.

```bash
./tools/node-install.sh
./start.sh --playtest --version 1.26.51
```

Если подходящего Node нет, установщик скачает **официальный Node 24.21.0**
в `.runtime/node/node-v24.21.0-linux-x64/` (или linux-arm64). Он сверяет SHA-256
с закреплённым в исходниках значением официального SHASUMS256.txt:
https://nodejs.org/download/release/v24.21.0/SHASUMS256.txt

Это контроль целостности по опубликованному хешу, не проверка GPG-подписи.
Смена закреплённой версии требует явного изменения исходника и CI.
Загрузка только HTTPS; архив проверяется до распаковки; запрещены выходы за
каталог, устройства, hardlinks и запись через symlinks. npm и npx используют
тот же runtime. Первая подготовка требует Интернета. Никаких sudo, изменений
/usr/bin, пакетного менеджера, ~/.bashrc, nvm default или пользовательских
проектов. PATH меняется только внутри запускающего процесса и его потомков.

`./start.sh --playtest --version 1.26.51` тоже автоматически выбирает runtime;
при отсутствии node_modules устанавливаются зависимости из package-lock.json.
Генератор данных и codec worker получают один и тот же Node. Нативным профилям
975/1001 для обычного запуска Node не добавляется как обязательная зависимость.
Команда `node --version` в твоём внешнем терминале может по-прежнему показывать
22 — это нормально. Проверить выбранный сервером Node:

```bash
NODE="$(python3 tools/node-runtime.py --no-download)"
"$NODE" --version
```

Ручной выбор существующей установки:

```bash
MPE_NODE=/opt/node24/bin/node ./start.sh --playtest --version 1.26.51
```

Явный MPE_NODE с неподходящей версией вызывает понятную ошибку, а не заменяется
другим исполняемым файлом. `MPE_NO_DOWNLOAD=1` запрещает **этому Node-установщику**
скачивание runtime; этот параметр не является глобальным сетевым sandbox.
Автоматическое скачивание поддержано для Linux x86_64/aarch64. На других
платформах требуется установленный Node >=24 и совместимое окружение сервера.

## Проверка задержек блоков

В игровом чате:

```text
/mpe perf
```

`level_chunks` и `block_updates` — пакеты, добавленные в очередь этой сессии.
`queued_bytes` — несжатые закодированные байты, НЕ фактический UDP-трафик.
`engine_roundtrip_ms` — последние 256 игровых действий от отправки в Rust до
обработки ответа шлюзом: включая очереди, запись на диск и обработку ответа
в PHP, но без клиентского FPS, рендера и сетевых подтверждений RakNet.
Первые p50/p95 равны null, пока нет действий. Просматривать счётчики желательно
стоя в одном месте после начальной загрузки мира. Установка/разрушение должны
увеличивать block_updates, не заставляя расти level_chunks для того же чанка.
Отказ/явная ресинхронизация и переход в новые чанки — отдельные случаи.
