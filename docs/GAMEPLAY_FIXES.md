# Игровые исправления после первого входа

Область этого изменения: дальнее строительство, простая вертикальная физика,
инвентарные перемещения и одновременные протоколы. Это не релиз полного Survival.

## Запуск нескольких версий

Новая конфигурация по умолчанию включает 975 (1.26.20), 1001 (1.26.30),
2193 (1.26.50/1.26.51). Каждый сеанс выбирает собственные кодек и палитру.
Номер в объявлении сервера — только один; он не ограничивает список принимаемых.

Существующий server.json не перезаписывается при обновлении. Для явного
перехода на эти три профиля остановите сервер и выполните один раз:

```bash
./start.sh --enable-multiversion
./start.sh
```

Первый вызов сохраняет предыдущий конфиг в уникальный `server.json.*.bak` и
меняет только protocols, advertise-protocol, experimental-codecs. Адрес,
порт, онлайн-авторизация, шифрование и каталог мира сохраняются. Копию конфига
не публикуйте: она может содержать ваши собственные параметры. Локальный Node
24 используется только для профиля 2193. Без параметра `--enable-multiversion`
явно выбранный ранее одноверсионный конфиг остаётся таким же.

`--playtest --version ...` намеренно остаётся одноверсионным диагностическим
режимом. Мультиверсия не означает наличия отображения моделей других игроков:
эта отдельная механика ещё не реализована.

## Дистанция блока

Раньше луч шёл к центру выбранной травы, то есть под поверхность. При клике
дальше трёх блоков луч мог попасть в соседнюю траву и ошибочно обнаружить стену.
Теперь проверяется поверхность выбранной грани. Предел 6.5 блока от глаз
сохранён; стены, занятое место и пересечение с игроком по-прежнему проверяются.
Это логика полных кубов, а не реализация геометрии всех блоков.

## Вертикальное движение

На входе явно отправляются metadata гравитации, столкновений и размеров игрока.
При обычном полёте вертикальная скорость способности исправлена с 1.0 на 0.05.
Координаты сети округляются после однократного вычитания высоты глаз 1.62.

Rust обрабатывает новый внутренний opcode 13: прыжок, падение в воздухе,
столкновение с полным кубом, приземление и выход из Creative-полёта. Гравитация
продвигается по входным клиентским тикам, не вторым независимым таймером.
Повтор старого тика не продвигает физику. Коррекции содержат текущую вертикальную
скорость вместо постоянного нуля. Старый opcode 3 оставлен для прежних IPC-тестов;
реальный gateway использует 13. Бинарник Rust необходимо пересобрать.

Не реализованы полноценные вода/лава, лестницы, ползание, сложные формы,
транспорт, ванильный step-up и полный античит. Автоматические тесты физики
не подтверждают ощущения и отрисовку в официальном клиенте: это следующий
ручной плейтест.

## Инвентарь

Окно личного инвентаря теперь использует постоянный window ID 0 вместо
создания второго инвентаря под новым ID. После успешного ItemStackRequest
ответ адресуется контейнерам, которые действительно использовал клиент
(hotbar, inventory, cursor). Полное содержимое не пересылается после каждого
успеха, чтобы не уничтожать цепочку клиентских предсказаний.

В мосте 1001 → 2193 явно преобразуется вариант сетевого ID стека:
объект `{type, id}` не должен сериализоваться как числовой ноль. Обратный
путь восстанавливает тип, включая отрицательные ID клиентских предсказаний.
Проверка типов остаётся включённой.

Реальный сетевой тест переносит 10 предметов из хотбара через курсор в
инвентарь, отправляя следующий запрос до ожидания первого ответа, возвращает
их и проверяет отклонение повтора запроса. Это не GUI-тест мышью.

## Честный список оставшегося

В этом изменении НЕ добавлены крафт, предметные сущности (выброс/подбор),
полный каталог игровых блоков/предметов, сохранение игрока, обычный worldgen,
мобы, редстоун и Survival. Текущие 11 строительных типов остаются ограничением.
Выброс нельзя выдавать за готовый, просто удалив предмет из инвентаря:
нужны сущность в мире, физика, подбор, лимиты и атомарное владение количеством.
Крафту нужны рецепты, сетевые ID, проверка ингредиентов и атомарное списание.

Следующий отдельный этап — канонический реестр StateId(u32)/ItemId с миграцией
IPC и сохранений, затем предметные сущности и базовые рецепты. Существующую
карту и журнал нельзя молча переинтерпретировать под новые ID.

## Проверки

```bash
./start.sh --unit
./start.sh --test
./tools/e2e.sh --version 1.26.20 --scenario creative
./tools/e2e.sh --version 1.26.30 --scenario creative
./tools/e2e.sh --version 1.26.51 --scenario creative
./tools/e2e.sh --multi
```

Последний тест держит три версии на одном экземпляре/порту. Клиент 2193 ставит
блок, клиент 975 ломает его, все три получают изменения со своими runtime ID.
Все автоматические сетевые сценарии используют offline-тестовую идентичность
в loopback с шифрованием. Онлайн-авторизация обычного сервера не отключается.
